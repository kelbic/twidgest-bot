# Маркетинг-скаут Twidgest

Отдельный Telegram-бот — личный ассистент основателя по продажам. Находит и
обогащает лиды (каналы 200–5000 подписчиков), оценивает «ведут ли канал
вручную», ищет ВЫГОРАЮЩИХ админов (кадэнс валится: decay < 0.6), готовит демо
по нише и черновик первого сообщения. Всё до кнопки «отправить» — автоматом,
сама отправка — только руками основателя (HIL).

## Запуск

```bash
# 1. Создать бота у @BotFather (например @TwidgestLeadsBot), токен в .env:
MARKETING_BOT_TOKEN=...

# 2. (опционально) переопределить дефолты:
MARKETING_DB_PATH=marketing.db
MARKETING_DAILY_LLM_CAP=100     # потолок в коде: 200
MARKETING_DAILY_DEMO_CAP=5      # потолок в коде: 10
MARKETING_DAILY_CARDS_CAP=10    # потолок в коде: 20
MARKETING_LLM_MODEL=...         # по умолчанию — OPENROUTER_MODEL_DEFAULT

# 3. Запуск (тот же venv, что у прода):
venv/bin/python -m marketing.main

# 4. Прод-деплой: deploy/twidgest-marketing.service (инструкция в шапке юнита).
#    НЕ включать юнит, пока MARKETING_BOT_TOKEN не в .env.
```

Переиспользует из прод-`.env`: `ADMIN_USER_ID`, `OPENROUTER_API_KEY`,
`TWITTER_API_KEY`. Прод-БД `twidgest.db` не открывается вообще; своя БД —
`marketing.db` (WAL, создаётся сама).

## Команды

| Команда | Что делает |
|---|---|
| `/addlead @channel [ниша]` | добавить лид |
| `/import` | список лидов следующим сообщением (`@channel [ниша]` или CSV `username,niche`) |
| `/queue` | следующая карточка из очереди qualified |
| `/leads [статус]` | счётчики по статусам / список лидов в статусе |
| `/lead <id>` | карточка конкретного лида |
| `/mark <id> replied\|trial\|paid\|dead` | ручное движение по воронке |
| `/note <id> текст` | заметка к лиду |
| `/stats` | воронка, конверсии, среднее время ответа |
| `/export` | CSV всех лидов |
| `/pause` / `/resume` | пауза воркеров (обогащение, фоллоу-апы) |

Кнопки карточки: ✅ Одобрить (текст отдельным чистым сообщением + демо + кнопка
«📤 Отправлено») · ✏️ Править (FSM: указания или готовый текст) · 🔁 Другой
черновик · 🎁 Сгенерировать демо · ❌ Скип · 🚫 Blacklist (opt-out навсегда).

## Пайплайн

`new` → (enrichment, раз в час, батч ≤5, t.me/s/ превью) → `enriched` →
(квалификация: эвристики + 1 батч-вызов LLM, fail-open) → `qualified`
(score ≥ 40) или `dead` → карточка админу (≤10/день, остальное в `/queue`) →
`approved` → `contacted` (фоллоу-ап через 4 дня, максимум один) → `replied` →
`trial` → `paid`. Терминальные: `dead`, `optout`.

Главный сигнал скоринга — **траектория кадэнса** (`decay = recent_ppw /
older_ppw`): выгорающий админ постит не рвано, а всё реже. Высокий `gap_cv`
без падающего decay (событийные ниши вроде F1) бонуса не даёт.

## Капы (жёсткие, в коде)

Дневные капы проверяются в `marketing/llm.py` и `marketing/demo.py` через
персистентные счётчики в БД (переживают рестарт). Env может капы только
уменьшить — потолки зашиты в `marketing/config.py` (`HARD_MAX_*`).
Превышение = вежливый отказ в карточке, не исключение.

## Правила безопасности (из ТЗ, зашиты в код)

- черновики без ссылок (валидатор в `copywriter.py` отбрасывает драфты с
  http/t.me), без обещаний роста, честное представление;
- opt-out свят: 🚫 → статус `optout` + blacklist навсегда, повторный импорт
  заблокированного канала — no-op;
- t.me/s/: ≤1 запрос/сек, кэш 24ч, таймаут 10с, один ретрай.

## Известные ограничения и блокеры

- **Dry-run с реальным токеном не прогнан**: разработка велась из-под
  пользователя без доступа к `/root/twidgest-bot/.env` (репо в `/root`,
  mode 700). Код готов к запуску, но первый живой прогон (`/addlead` на
  2–3 реальных канала → карточка) нужно сделать после добавления
  `MARKETING_BOT_TOKEN` — чеклист в разделе «Запуск».
- **Systemd-юнит от выделенного пользователя не заработает, пока репо в
  `/root`** — варианты в комментариях `deploy/twidgest-marketing.service`
  (перенести в `/opt` или ACL).
- Кэш превью t.me и кэш твитов — in-memory (сбрасываются рестартом);
  счётчики капов — в БД (не сбрасываются).
- Демо генерируется промптом ближайшей известной ниши
  (`tech_ai`/`crypto`/`sports`/`longevity`, иначе `general`) — свободная ниша
  лида влияет на подбор источников, но не на стиль промпта.

## Отложено (не MVP)

- TGStat API — заглушка `marketing/sources_tgstat.py` с TODO-интерфейсом.
- Kwork/fl.ru не парсим (правила площадок) — такие лиды руками через `/addlead`.
- Автоопределение ответов лида (бот не видит личку основателя) — статусы
  `replied`/`trial`/`paid` двигаются руками через `/mark`.
